## Coordinates
* There are two main coordinate systems; the robot can use both
	* Cartesian
		* Typical x/y coordinate system
		* $(x, y)$; x in first slot, y in second
	* Polar
		* Usees angle and radius
		*  $(radius, \theta)$
### Cartesian Coordinates
* Numbers which indicate the location of a point **relative** to a **fixed reference** point (the origin), being its shortest **(perpendicular)** distances from two fixed axes (or three planes defined by three fixed axes) which intersect at right angles at the origin
![Cartesian Coordinates](https://i.ibb.co/1YLqWf76/Screenshot-2026-10-23-113014.png)

### Polar Coordinates
* When each **point** on a plane of a 2d coordinate system is decided by a distance from a reference point and an angle is taken from a reference direction
![Polar Coordinates](https://i.ibb.co/JFyX7r5v/image.png)
### The difference
* Cartesian is based off **triangles**
* Polar is based off **circles**
* They both are commonly used and have their own applications; in the end, it is whichever will be easier in the situation
## Relativity
* The absence of standards of absolute and universal application
### Galilean Relativity
* Coordinate systems also depend on the orientation of the plane
* Think of lefts and rights, my left and your left are going to be at different angles if we are at different angles
* This same idea is applied to coordinate systems
#### Robot Centric (relative)
- Coordinates based off the robots current position
- Current angle and orientation of the robot effects what the coordinates result in
#### Field Centric (absolute)
- Based on the field orientations
- Not impacted by robot orientation

## Vectors and trig
- Vectors are a quantity that includes magnitude **and** direction
- Think about velocity or acceleration, where you need a speed and an angle, not just speed
- Now we can give the robot a specific vector that tells it where to go and how fast
![Vectors](https://i.ibb.co/q3YBb3Zq/image.png)
* In this way, you can use a coordinate to determine the position of the vector, which would define the **speed** and **direction** of the robot
### Theta $(\theta)$
- Thera $(\theta)$ is used to represent an unknown angle
- There are two main ways to measure an angle:
	- With degrees $(0\degree$to $360 \degree)$ 
	- With radians $(0$ to $2\pi)$
- Just like the coordinate systems, they both can be used to represent the same angle
- To convert between the two, multiply by:
	- $\frac{180}{\pi}$ for rads to degrees
	- $\frac{\pi}{180}$ for degrees to rads

```java
// Basic line of code that stops the robot from moving
new InstantCommand(() -> swerve.drive(new Translation2d(0, new Rotation2d()), 0.0, true))

// Breaking it down
new InstantCommand(...)

```
```java
new Translation2d(0, new Rotation2d())
```
This creates a new instance of **Translation2d** which takes in a distance and rotation (vector!). This takes in an arbitrary "distance" (for of vector) and the angle (direction) that you want the robot to go. We are using polar coordinates in this case. The new Rotation2d simply converts the degree into x and y (cartesian) using sin and cosine.
If there's no value:
```java
public Rotation2d() {
	m_value = 0.0;
	m_cos = 1.0;
	m_sin = 0.0;
}
```
If there is a value:
```java
public Rotation2d(@JsonProperty(required = true, value = "radians") double value) {
	m_value = value;
	m_cos = Math.cos(value);
	M-sin = Math.sin(value);
}
```
This second instance of rotation (the 0.0) is the robots **rotation per second** during the "drive" command. This takes in a **speed**, and the **direction of rotation** (left or right) is determined by the sign **(positive / negative)**

The final parameter is to tell the robot how it is going to be getting the measurements and determining its **position**. This is a boolean param; only true and false. True tells it to use **Open Loop**, which is percent output, while false tells it to use **Closed Loop**, which is exact velocities and **PIDs**.
![Basic impl summary](https://i.ibb.co/qMfsgSFf/image.png)
Another useful command that is used a lot is **WaitCommand**. This command simply adds a delay for a duration in **seconds**.
```java
new WaitCommand(1); // delay of 1 second!
```
